# WasteOps Public Screens — Product-Specific Design Override

This override applies to sign-in and resident collection-request screens. It supersedes the unrelated LMS academic typography and mood described in the generated master while retaining the reference skill’s form-label, contrast, visible-focus, responsive and reduced-motion criteria.

Keep the dark-teal WasteOps identity and a small circular-material mark, but use a quiet, single-column content layout with clear headings and no marketing filler. Make sign-in and collection request distinct tasks. State that the public form records a request and does not promise dispatch or sensor monitoring. Avoid exposing staff routes, operational metrics, request details or tenant identifiers.

Use labeled inputs, visible required/optional status, precise length and format guidance, a generic login error that does not reveal whether an account exists, and a non-sensitive request reference after successful submission. Status feedback must be keyboard-reader compatible and must not rely on color alone. Keep controls comfortable on mobile and preserve `prefers-reduced-motion`.
